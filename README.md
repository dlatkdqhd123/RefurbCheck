# RefurbCheck 1.4.0 — 갤럭시 리퍼폰 한 번에 점검

공장 초기화 후, 앱·설정 백업을 복원하기 전에 실행하는 무료 Android 점검 앱입니다.
앱을 열면 검사 자료 확인, 현재 프로필 검사, 가능한 삭제 승인 연결, 조치 결과 재확인을 한 흐름으로 진행합니다. 현재 프로필의 앱 파일·설치 정보·활성 권한·부팅 상태·하드웨어 키 증명을 수집하고, 근거가 충분한 파일 지문 일치 앱은 삭제 직전 재검증합니다. 사용자가 승인해야 하는 Android 창과 직접 바꿔야 하는 설정은 해당 단계에서 안내합니다.
**공장 순정·모든 악성코드 부재·물리 하드웨어 무변조를 인증하지 않습니다.**

## 다운로드와 설치

1.4.0은 배포 검증을 거쳐 초안으로 준비하며, 검증 결과에 대한 사용자 승인 후 공개합니다. 공개 전에는 아래 1.4.0 다운로드 링크를 사용할 수 없습니다. 기존 공개 버전은 1.3.0입니다.

- [RefurbCheck 1.4.0 APK](https://github.com/dlatkdqhd123/RefurbCheck/releases/download/v1.4.0/RefurbCheck-1.4.0.apk)
- [릴리스 설명·검증 자료](https://github.com/dlatkdqhd123/RefurbCheck/releases/tag/v1.4.0)
- [전체 소스 ZIP](https://github.com/dlatkdqhd123/RefurbCheck/releases/download/v1.4.0/RefurbCheck-1.4.0-source.zip)
- [APK SHA-256](https://github.com/dlatkdqhd123/RefurbCheck/releases/download/v1.4.0/RefurbCheck-1.4.0.apk.sha256)

Android 8.0(API26) 이상. Wi-Fi로 **APK**를 받아 설치하고 실행하면 검사합니다. 처음 설치할 때 브라우저/파일 앱의 외부 앱 설치 허용이 필요할 수 있습니다. 설치 후 해당 허용과 삼성 보안 위험 자동 차단 설정을 다시 확인하세요. 소스 ZIP은 설치 파일이 아닙니다.

**v1.3.0을 이미 설치했다면:** 같은 서명키를 사용하므로 v1.4.0 APK를 업데이트 설치할 수 있습니다. 앱을 제거할 필요가 없으며 저장된 설정과 검사 자료를 유지합니다. 꺼 둔 자동 자료 확인·삭제 승인 연결 설정을 업데이트가 다시 켜지 않습니다.

v1.2.0은 다른 서명키를 사용하므로 업데이트 설치가 안 됩니다. 필요한 검사 결과를 JSON으로 저장하고 사용자가 v1.2.0을 제거한 뒤 새로 설치해야 합니다. 제거하면 앱 전용 자료·설정이 삭제됩니다. 초기화 후 처음 설치하는 기기는 APK를 바로 설치합니다.

- 앱 ID: `io.github.refurbcheck`, versionCode `5`
- v1.3.0과 동일한 APK 서명 인증서 SHA-256: `d02b8c5cbcde0ad3fbd3eb9e4c66e28094a27cf4f7a8472d309f84d825184ceb`
- APK 서명키와 검사 자료 서명키는 별개이며 공개 소스·GitHub Actions에 개인키를 포함하지 않습니다.

## 1.4.0: 실행부터 결과까지 이어서 진행

첫 화면에서 현재 단계와 진행 상태, 이번 실행의 조치 결과를 함께 확인할 수 있습니다. 검사 뒤 다른 탭을 찾아 들어가 자동 조치를 시작할 필요가 없도록 실행 흐름을 연결했습니다.

| 단계 | 앱이 이어서 수행하는 일 | 사용자 확인이 필요한 경우 |
|---|---|---|
| 자료 확인 | 저장된 설정과 Wi-Fi 조건에 맞으면 서명된 검사 자료 확인 | 자동 확인을 껐거나 Wi-Fi가 없으면 기존 자료로 진행; 자료 오류·만료는 별도 표시 |
| 검사 | 앱 파일·서명·설치 출처·관리 권한·시스템 신호·키 증명 점검 | 읽기 제한·미지원·실패는 미확인으로 남김 |
| 가능한 조치 | 적격 일반 앱마다 현재 파일·설치 상태·자료 유효성을 다시 확인하고 Android 삭제 승인창 연결 | 각 삭제는 Android 승인이 필요; 설정 변경은 안내된 시스템 화면에서 직접 수행 |
| 재확인 | 삭제 창 복귀 후 실제 설치 상태를 확인하고 필요한 최종 재검사 진행 | 취소·실패·확인 제한이면 보류 사유 표시 |
| 요약 | 실제 미발견 확인 수, 보류·수동 확인·미확인 항목을 함께 표시 | ‘흐름 완료’는 순정 인증 또는 모든 위험 해결을 뜻하지 않음 |

중지하거나 삭제를 취소하면 다음 앱의 승인창을 계속 띄우지 않습니다. 화면 회전이나 다른 화면에서 복귀할 때 중복 작업을 시작하지 않으며, 앱이 전면에 없으면 새 삭제 승인창을 열지 않습니다. 자동 연결할 대상이 없다면 최초 검사 결과로 정리하므로 형식상 단계를 채우기 위한 동일 재검사를 반복하지 않습니다. 자세한 기준은 [한 번에 점검 흐름](docs/one-run.md)을 확인하세요.

## 사용 흐름

1. 가능한 경우 판매자에게 기업 관리 등록 해제를 확인하고 공식 절차로 초기화합니다. 백업 앱·설정을 복원하기 전에 검사합니다.
2. Wi-Fi에 연결해 APK를 설치하고 엽니다. 기본값은 **초기화 직후 정책** 및 **Wi-Fi 자료 확인** 사용입니다. 검사와 가능한 조치 연결이 첫 화면에서 이어집니다.
3. Android 삭제 승인창이 나오면 대상과 근거를 확인해 승인합니다. 승인하지 않거나 중지하면 자동 진행을 보류합니다. 삭제 대상을 찾지 못했다고 전체 기기가 안전한 것은 아닙니다.
4. 요약에 남은 설정 항목은 안내된 화면에서 직접 확인·변경합니다. 돌아오면 해당 결과를 재검사하며, 화면을 열었다는 이유만으로 해결됐다고 표시하지 않습니다.
5. 필요하면 앱별 근거와 상세 결과를 펼치거나 JSON을 저장합니다. JSON에는 앱 목록·인증서 등이 포함되므로 전달할 상대를 확인하세요.

다운로드 실패 시 사용 가능한 기존 자료로 검사를 계속할 수 있습니다. 만료·시각 오류·자료 보관 오류가 있으면 자동 삭제 연결을 보류합니다. 초기화 직후라도 정상 시스템 앱이나 스토어 자동 설치 앱이 있을 수 있으므로, 예상하지 않은 앱이라는 이유만으로 삭제하지 않습니다.

## 자료 갱신과 개인정보

업데이트는 고정된 GitHub HTTPS 주소에서 데이터 ZIP을 받습니다. 리다이렉트를 따르지 않으며 앱 목록·APK·보고서·기기 식별자를 업로드하지 않습니다. 서버는 접속 IP 등 일반 연결 정보를 볼 수 있습니다. 광고·분석 SDK·백그라운드 상주 서비스는 없습니다.

RSA3072 서명과 개별 파일 SHA-256, 순번, 최대 30일 유효기간, 원자료 수집일, 정확한 파일 구성을 검증한 뒤 앱 전용 영역에 원자적으로 교체합니다. 실패하면 기존 자료를 유지합니다. 이미 수용한 순번보다 낮은 자료와 같은 순번의 다른 자료는 거부합니다. 앱 데이터 삭제/제거 또는 침해된 OS의 전역 복원까지 막는 하드웨어 rollback protection은 아닙니다. 완전한 TUF 구현도 아닙니다.

현재 기본 자료 구성일은 2026-11-06입니다. 수집 날짜는 각 원자료의 출시 날짜나 검출률을 뜻하지 않습니다. ClamAV 전체 엔진·YARA-X·ML 모델은 포함되지 않으며 신규 악성코드 탐지율을 측정하지 않았습니다. 초기 signed update #1은 동일 참조 집합의 배포 경로를 분리한 것으로, 새로운 악성 샘플을 추가했다고 표시하지 않습니다.

## 빌드와 회귀 테스트

JDK17, Android SDK platform35 및 build-tools35.0.0이 필요합니다. 일반 앱 소스는 Java8 수준입니다. 제공된 공개 apksig JAR의 지문을 빌드 전에 확인합니다.

```bash
python3 tools/build_apksig_port.py
python3 tools/build_apk.py --sdk-root /path/to/android-sdk \
  --keystore /private/path/refurbcheck-release.p12 \
  --password-file /private/path/apk-password.txt
REFURBCHECK_TEST_APK="$PWD/dist/RefurbCheck-1.4.0.apk" bash tests/run_all_tests.sh
```

개인키와 암호는 저장소 밖에 두세요. v1.3.0에서 업데이트 설치하려면 기존 v1.3.0 개인 서명키가 필요합니다. Gradle 빌드도 가능하며 `REFURBCHECK_KEYSTORE` 등 기존 환경변수를 사용합니다. 검증용 debug/test 키를 정식 배포 키로 사용하지 마세요.

GitHub 배포는 고정 APK·인증서·소스 입력 지문 확인, 호스트 회귀 테스트, Android API26·36 실행 검사를 모두 통과해야 게시됩니다. Android 검사에서는 임시 서명 사본으로 배포 APK의 코드·리소스를 실행하고, 원본 배포 APK의 v1.3.0 → v1.4.0 업데이트 설치와 시작도 확인합니다. 개인 배포 서명키는 CI에 넣지 않습니다. 구체적인 실행 결과는 해당 버전의 Actions 기록을 확인하세요.

릴리스 초안은 두 Android 검증과 호스트 검증을 통과한 뒤 새 태그로만 준비하며 기존 태그·파일을 덮어쓰지 않습니다. 초안 공개는 결과를 검토한 사용자의 승인 후 별도로 진행합니다. 기본 `main`의 별도 prototype 소스는 유지하고 정식 앱은 `release/1.4.0` 및 `v1.4.0` 태그에 둡니다.
