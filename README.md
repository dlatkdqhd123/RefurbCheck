이 브랜치는 `io.github.refurbcheck` 패키지의 검증된 1.2.0입니다. `main`에 보존한 0.2 시험판은 `io.github.dlatkdqhd123.refurbcheck.prototype`라는 별도 앱입니다. 0.2 시험판을 설치했다면 1.2.0은 별도로 설치되며, 실행 화면 상단의 버전을 확인하세요. 이 대화에서 제공한 1.0.0·1.1.0과는 같은 릴리스 서명키를 사용합니다.


갤럭시에서 **OS·루팅·설치 APK·보안 설정의 근거를 모으고, 필요한 조치 화면으로 연결한 뒤 다시 검사하는 무료 오프라인 Android 앱**입니다. 한국어 화면이며 처음 실행하면 자동으로 검사합니다. **공장 초기화 직후 모드가 기본으로 켜져 있어, 알려진 악성·감시 파일과 정확히 일치한 일반 앱은 삭제 직전 재검증 후 Android 삭제 확인창으로 이어집니다.** 사용자가 승인한 뒤 다음 대상을 처리하고 마지막에 전체 재검사합니다. 이후에는 다시 점검 버튼으로 새 검사를 시작할 수 있습니다.

**공장 출고와의 전체 일치, 악성코드의 완전한 부재, 물리 부품 무변조를 인증하는 제품은 아닙니다.** 읽지 못한 항목·미지원 기능·실시하지 않은 검사를 `확인 불가`로 남깁니다. 모델과 One UI는 실행한 기기에서 관측하며 OS 자기 보고라는 한계를 표시합니다.

## 휴대전화에서 설치

공장 초기화 후 앱·설정 백업을 복원하기 전에 사용하세요. 자동 조치 모드는 직접 설치한 감시·관리 앱이 없는 상태를 전제로 합니다. 원치 않으면 검사 중 또는 결과/조치 화면에서 해당 모드를 끌 수 있습니다.

1. 제공된 `RefurbCheck-1.2.0.apk`를 Wi-Fi로 다운로드합니다. GitHub에 게시한 경우 **Releases → Assets → APK** 또는 저장소 `release/`의 **Download raw file**을 이용합니다. 소스 ZIP은 설치 파일이 아닙니다.
2. 파일을 열어 Android 설치 화면에서 승인합니다. Android 8.0/API 26 이상을 대상으로 하며 루팅·ADB·PC 연결·가입·API 키가 필요하지 않습니다.
3. 갤럭시의 보안 위험 자동 차단이 외부 APK 설치를 막을 수 있습니다. 출처와 파일을 확인한 뒤 본인이 설치 여부를 결정하세요. 앱이 자동 차단이나 Play Protect를 끄지 않습니다. 설치 후 브라우저/파일 앱의 외부 설치 허용을 끄고 자동 차단을 다시 켜세요.
4. **리퍼폰 점검**을 실행하면 검사합니다. **결과 → 각 항목의 근거**, **앱 → 개별 APK 정보**, **조치 → 필요한 설정/공식 진단**, **안내·비교 → 참고 보고서 비교**를 이용합니다.
5. 설정 화면에서 돌아오면 자동 재검사합니다. 자동 삭제 진행 중에는 각 앱의 제거 여부를 확인하고 다음 대상으로 이어지며, 마지막에 전체 재검사합니다. 화면을 열었다는 사실과 신호가 다시 관측되지 않은 결과를 구분합니다.

Java DEX 기반 공통 APK이므로 ARM/ARM64/x86/x86_64용 네이티브 바이너리를 따로 요구하지 않습니다. 실제 기기별 실행 검증 범위는 [검증 기록](docs/validation.md)을 확인하세요. v1.0.0·v1.1.0과 같은 개인 릴리스 키로 서명해 업데이트할 수 있습니다. debug 키로 빌드한 앱과는 업데이트 호환되지 않습니다.

### 검사 범위·취소

APK 검사는 파일당 1 GiB, 전체 파일 해시·서명·압축 원본 재읽기를 합해 8 GiB, 검사 시간 3분의 협조적 예산을 둡니다. 사용자 앱을 먼저 처리합니다. 각 읽기와 검증 단계 사이에 취소·예산을 확인하지만 OS 호출이나 검증기 내부 연산을 강제로 끝내는 별도 격리 프로세스는 아닙니다. 따라서 정확히 3분에 항상 종료한다는 보장은 아닙니다.

파일 경로와 열린 파일의 식별자·크기·수정 시각, 패키지 버전·업데이트 시각을 전후 비교합니다. 변경된 파일의 잠정 해시는 `observedSha256`로 분리하고 확정 해시·IOC 일치 근거에서 제외합니다. 중단·읽기 실패·미지원·변경된 파일·0개 검사 결과를 전체 완료로 처리하지 않습니다. 실제 수집량과 미확인 수, 중단 사유가 JSON과 화면에 남습니다.

## 즉시 조치 기능

초기화 직후 모드의 흐름은 **검사 → 정확 일치 일반 앱 선택 → 현재 파일·자료 재검증 → Android 삭제 승인 → 제거 여부 재조회 → 다음 앱 → 전체 재검사**입니다. 삭제를 취소하거나 제거를 확인하지 못하면 자동 진행을 멈춥니다. 앱의 자료 판정은 그대로 보존하며, 이 모드가 감시 앱의 비동의 감시 사실을 입증한다는 뜻은 아닙니다. 시스템 앱과 이 점검 앱은 자동 대상에서 제외합니다.

| 발견/필요 사항 | 앱에서 시작하는 동작 | 다시 확인하는 범위 |
|---|---|---|
| 공개 악성·감시 파일 지표와 정확히 일치한 일반 앱 | 초기화 직후 모드에서 근거가 된 APK·현재 버전·참조 자료를 재검증하고 Android 삭제 확인창을 자동으로 요청 | 제거 여부 재조회, 남은 대상 순서대로 처리, 마지막 전체 재검사 |
| 모르는 접근성·알림 접근 앱 | 해당 설정 화면 열기 | 현재 프로필의 활성 항목 재관측 |
| 모르는 기기 관리자·사용자 CA | 보안 설정과 메뉴 경로 안내 | 노출된 관리자·인증서 재관측 |
| VPN·프록시·키보드·민감 권한 | 해당 공개 설정 화면 열기 | 앱이 읽을 수 있는 설정만 재확인 |
| 디버깅·개발자 옵션 | 개발자 옵션 열기 | 제한된 0값으로 해결 완료 판정 금지 |
| 악성코드 추가 검사 | 삼성 앱 보호 또는 Play Protect 열기 | 외부 앱 결과를 자동으로 읽거나 통과 처리하지 않음 |
| 자동 차단·외부 설치 허용 | 보안 설정 및 설치 출처 설정 열기 | 자동 차단 활성화 여부는 직접 확인 필요 |
| 오래된 패치 | 삼성 소프트웨어 업데이트 경로 안내 | 다음 검사에서 OS가 보고한 패치 날짜 확인 |
| 부품 이상/진위 의심 | Samsung Members 진단 및 삼성 공식 점검 안내 | 기능 진단과 물리 부품 무변조 인증을 구분 |
| OS 변조·Knox·인증서 폐기 의심 | 삼성 공식 점검 안내 | 앱 내 자동 복구를 주장하지 않음 |

새 참조 자료의 삭제 전 검증은 45초/3 GiB 예산, 같은 FD의 검사 전후 전체 재해시, APK 경로 집합·UID·버전·갱신 시각, 기기 관리자 상태를 확인합니다. 근거가 된 APK의 파일·ZIP 검사 미완료, 파일·자료 변경, 잘린 일치 목록, 활성 관리자 권한이나 확인 불가 상태는 설명과 함께 보류합니다.

기존 MVT의 APK 전체 SHA-256 정확 일치에는 기존 30초/2 GiB 경로를 우선 사용합니다. 일치한 현재 APK를 재해시하고 MVT 자료·버전·갱신 시각·재검증 중 경로 구성 변화를 확인합니다. 이 경로는 ZIP 전체 검사 완료나 기기 관리자 사전 조회를 요구하지 않으며 관리자·기업 정책에 따른 실제 삭제 제한은 Android가 처리합니다. 기기 전체 검사가 미완료여도 독립적으로 확인된 해당 파일의 근거는 보존하며, 이를 기기 전체 안전 판정으로 확대하지 않습니다.

삭제는 시스템 앱·이 앱 자체·근거가 변경되거나 부족한 앱에는 제공하지 않습니다. 위험 권한이나 낯선 앱 이름만으로 자동 삭제하지 않습니다. 가져온 참고 보고서도 삭제 입력으로 쓰지 않습니다. 최종 삭제 승인과 실제 제거는 Android가 수행하며, 승인하면 해당 앱 데이터도 삭제됩니다. 재검증과 시스템 승인 사이에 다른 설치가 일어날 수 있는 시간 간격까지 완전히 제거하는 구조는 아닙니다.

설정 화면·삼성 앱을 열고 돌아온 것만으로 ‘치료 완료’를 기록하지 않습니다. `화면 열림`, `복귀`, `현재 목록 미발견`, `신호 미재발견`, `확인 필요 유지`, `자동 확인 불가`를 구분해 조치 기록에 남깁니다. 제거 후에도 다른 프로필·잔존 코드·침해된 OS의 복구는 검증하지 않습니다.

일반 앱은 다른 앱의 관리자/인증서를 임의 제거하거나 시스템 보안 설정을 몰래 바꿀 수 없습니다. 초기화·펌웨어 플래싱·부트로더 재잠금은 구현하지 않았습니다. **실제 Knox Warranty Bit가 변경된 경우 앱으로 되돌릴 수 없습니다.** OS가 보고한 warranty 속성을 실물 확인이나 삼성 서버 증명과 동등하게 취급하지 않습니다. [삼성 공식 설명](https://docs.samsungknox.com/admin/knox-admin-portal/kbas/kba-360039680233/)

## 판정과 보고서

- `중요 징후`: 우선 확인할 강한 관측. 기존 MVT 자료와 APK 전체 SHA-256이 정확히 일치한 경우, 지원 조건을 갖춘 부팅 검증 실패 등입니다. 추가 백신·감시 자료 일치는 별도의 출처·분류를 보존한 `확인 필요`로 표시합니다.
- `확인 필요`: 정상 사용에서도 발생할 수 있으며 사용자·제조사 확인이 필요합니다.
- `확인 불가`: 미지원, 읽기 실패, 미실시, 시간·크기 제한 등이며 통과가 아닙니다.
- `참고 관측`: 해당 범위의 정보 또는 제한된 지표 미발견입니다.

점수나 ‘100% 안전’을 표시하지 않습니다. 경고가 없어도 미검증 영역이 있으면 종합 결과는 `미검증 항목이 남아 있습니다`입니다. 공장 원본·악성코드 부재·물리 하드웨어 검증 완료 필드는 항상 false입니다. 보안 패치 180일 기준은 앱의 검토 기준이며 공식 최신 버전 판정이 아닙니다.

JSON v2에는 보고서 ID, 규칙 버전, 기기 시각, 항목별 관측 시각·증거 출처, APK 범위·지표 출처, 키 증명·인증서, 조치 기록이 들어갑니다. 기기 시각도 독립적으로 인증하지 않습니다. 보고서에 대한 외부 전자서명이나 증거 보존 서비스를 제공하지 않습니다.

보고서는 Android 파일 선택기로 저장합니다. 저장 화면 중 프로세스가 종료되는 경우를 위해 사용자 요청 시 앱 전용 캐시에 사본을 두며, 성공·취소 시 삭제합니다. 캐시가 OS에 의해 제거되면 재저장이 필요합니다. 가져오기는 8 MiB·엄격 UTF-8·중첩 깊이 제한과 JSON 형식 검사를 거치며, v1/v2 참고 보고서를 지원합니다. **개인 보고서를 공개 GitHub에 올리지 마세요.**

## 자료 시점과 갱신

내장 참조 자료 구성일은 2026-11-06입니다. ClamAV 해시 자료는 main 63(2025-12-16)에서 선택했고 daily 28175(2026-11-06)의 폐기·허용 목록을 반영했습니다. ESET·Échap·MVT의 고정 commit과 실제 원자료 날짜를 카탈로그에 남겼습니다. 15,645개는 참조 서명 수이며 탐지율 또는 현재 유포 중인 서로 다른 악성 앱 수가 아닙니다. 자동 인터넷 갱신은 없으며 새 자료는 앱 업데이트로 받습니다. 기기 시각상 구성 후 30일을 넘기거나 시각이 부정확하면 최신성 확인 필요를 표시합니다.

## 개인정보와 권한

Manifest 권한은 `QUERY_ALL_PACKAGES`, `ACCESS_NETWORK_STATE`, `REQUEST_DELETE_PACKAGES`입니다. **INTERNET 권한, 광고, 자동 업로드, 분석 SDK, 원격 명령, 백그라운드 서비스가 없습니다.** 다운로드 후 앱 자체 검사는 오프라인입니다. 사용자가 누른 외부 삼성 앱·Play 스토어·공식 웹 자료는 해당 앱이 네트워크를 사용할 수 있습니다.

IMEI·일련번호·연락처·사진·계정 비밀번호를 수집하지 않습니다. 이 앱에 접근성·기기 관리자·루트 권한을 부여하라고 요청하지 않습니다. 임시 키 증명 키는 반환 후 삭제합니다. 제조사 KeyStore가 응답하지 않으면 15초 이후 확인 불가를 반환하며, 호출 자체가 멈춘 상태에서 즉시 키 정리를 보장하지는 않습니다. Android 앱 백업은 비활성화했습니다. 결과와 이번 실행의 조치 기록은 메모리에 보관하며 프로세스 종료 시 사라집니다. 저장 요청에 따른 보고서 사본은 별도입니다.

## 빌드·테스트

JDK 17, compile/target SDK 35, Build Tools 35.0.0, AGP 8.9.1, Gradle 8.11.1을 사용합니다. apksig-android JAR은 저장소에 고정하고 SHA-256을 검사합니다. JSON-java는 호스트 테스트용이며 APK에 포함하지 않습니다.

```bash
./gradlew :app:assembleDebug
```

debug APK는 개발용 서명입니다. 정식 업데이트 빌드는 기존 개인키를 보존하고 `REFURBCHECK_KEYSTORE`, `REFURBCHECK_STORE_PASSWORD`, `REFURBCHECK_KEY_ALIAS`, `REFURBCHECK_KEY_PASSWORD` 환경변수를 설정해 `./gradlew :app:assembleRelease`를 사용합니다. 개인키·암호를 Git에 커밋하지 마세요.

공식 SDK 도구만 사용하는 재현 가능한 빌드 절차도 제공합니다(서명 시각/도구 환경까지 포함한 비트 동일 재현성 보증은 아닙니다).

```bash
python3 tools/build_apk.py \
  --sdk-root /absolute/path/android-sdk \
  --keystore /private/path/refurbcheck-release.p12 \
  --password-file /private/path/keystore-password.txt

bash tests/run_attestation_tests.sh
bash tests/run_report_tests.sh
bash tests/run_apk_tests.sh
bash tests/run_remediation_tests.sh
bash tests/run_malware_tests.sh
bash tests/run_malware_remediation_tests.sh
```

실제 배포 APK는 공식 SDK 도구 경로로 컴파일·DEX 변환·서명·검증했습니다. Gradle/Actions 실행 여부와 가상기기/실물 검증 범위를 [validation.md](docs/validation.md)에 구분해 기록합니다.
