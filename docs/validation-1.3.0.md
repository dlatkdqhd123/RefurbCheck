## Android 실행 검증과 게시 조건

공개 v1.3.0 릴리스는 `.github/workflows/release.yml`의 API 26·36 실행 작업이 모두 성공한 경우에만 게시됩니다. 완료 여부와 실행 로그는 릴리스 커밋의 GitHub Actions run을 확인하세요. 아래 절차와 실제 실행 결과를 구분합니다.

`tests/android-v13/run_ci.sh`는 배포 APK 사본을 임시 CI 키로 재서명하고 별도 testOnly instrumentation APK와 함께 실행합니다. DEX·AndroidManifest·리소스·자산 및 모든 비서명 ZIP 항목은 정식 APK와 바이트 단위로 같아야 합니다. 배포 개인키는 CI에 전달하지 않습니다.

임시 사본에는 v2·v3 서명을 사용합니다. SDK 35의 재서명 과정에서 v1 메타데이터를 다시 추가하면 기존 서명 블록 앞의 정렬 패딩이 ZIP 항목 사이로 이동하는 현상을 재현했습니다. 이 구조를 통과시키기 위해 생산 파서를 완화하지 않았습니다. 임시 사본에서 v1 서명을 생략하고, 항목 사이의 빈 공간·숨은 데이터를 거절하는 회귀 테스트를 추가했습니다. 원본 배포 APK는 26개 직접 파일과 2,470,703바이트의 압축 해제 내용을 정상적으로 검사하며, 이를 독립적인 `java.util.zip.ZipFile` 결과와 교차 확인했습니다.

실행 검사는 실제 Android API의 설치 정보 분기, 관리 상태, 자기 APK 해시·서명, 서명 자료 가져오기·변조 거부·기존 자료 보존, Android 암호 공급자의 ECDSA·v3.1, 공식 공장 인증서·RKP 인증서, 키 증명의 UNKNOWN 처리를 확인합니다. 설치된 임시 사본의 내부 파일 검사 완료 여부와 정확한 원본 배포 APK의 내부 파일 검사도 각각 확인합니다. 원본은 읽기 전용 테스트 자산으로 검사하며 이 단계에서 설치하거나 실행하지 않습니다.

최종 JSON, 통과 항목, API, 정확한 테스트 대상 해시와 instrumentation 결과 코드를 검사합니다. `am instrument -w -r`의 원시 결과를 사용하며 셸 종료코드만으로 성공 처리하지 않습니다. 검사 통과 후 임시 앱들을 제거하고 정확한 배포 서명 APK를 설치하여 앱 시작을 별도로 확인합니다.

## 아직 확인하지 않은 것

실제 Galaxy/One UI별 동작과 성능, 물리 부품·전체 펌웨어 무변조, 제조사별 순정 기준, 실제 악성코드 탐지율·오탐률, 0-day·새 악성군, 독립 원격 키 증명은 검증하지 않았습니다. 무해한 fixture의 정확 일치·구조 실패 테스트를 실제 악성코드 정확도로 표시하지 않습니다. 새 v1.3 Android 시험에서는 삭제 확인 UI에서 실제 앱 삭제를 수행하지 않습니다. v1.2에서 기존 조치 흐름을 검사한 기록은 별도 버전 기록으로 남깁니다.
